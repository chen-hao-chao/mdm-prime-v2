A Principled Subtokenizer Design

A subtokenizer is an invertible mapping that converts each token into a sequence of $\ell$ sub-tokens, letting the diffusion process denoise at a finer granularity than whole tokens. This work identifies two open questions about the subtokenizer $\ff_\ell$: (1) what functional form should it take, and (2) how should the granularity $\ell$ be chosen?

We answer both and turn the analysis into two off-the-shelf techniques: (1) an index shuffling operation that encodes high-entropy sub-tokens, and (2) setting $\ell=\lceil \log_2 V\rceil$, under which $\ff_\ell$ performs binary encoding.

Technique 1: Index Shuffling

The training loss is minimized when sub-tokens carry as much entropy as possible. But sub-tokens produced by directly base-$b$-encoding the token indices from commonly-used Byte-Pair Encoding (BPE) tokenizers are low-entropy: BPE assigns small indices to frequent tokens, so token probability ends up inversely proportional to the token index (see the left subplots with title `without Shuff' in Fig. 3 (a) and (b)).


Figure 3. (a) Token probability and (b) cumulative distribution function (CDF) over token indices of the GPT-2 tokenizer evaluated on the C4 dataset. The left and right subplots of (a) and (b) show setups without and with index shuffling, respectively. The gray dashed line in (b) represents the CDF of a uniform token distribution.

To fix this, we randomly shuffle the token indices before base-$b$ encoding, scattering similar probability mass across sub-token slots. This pushes sub-token entropy to within a fraction of a bit of the theoretical maximum for every granularity we tested (results on C4 with the GPT-2 tokenizer, $V=50{,}257$):

Technique 2: Binary Encoding

The granularity $\ell$ itself also matters. The best achievable loss never increases as $\ell$ grows, and we confirm this trend tracks downstream accuracy too, not just loss (170M-parameter models on SlimPajama, ARC-e; also see Fig. 4(b)). So we pick the maximum viable granularity $\ell=\lceil \log_2 V\rceil$, under which $\ff_\ell$ encodes tokens into binary sub-tokens.


Implementation via Lookup Tables

The two techniques give the subtokenizer $\ff_\ell= \ff_\text{base-$b$}\circ \ff_\text{shuffle}$: shuffle the token indices, then binary-encode them. The entire operation is implemented using lookup tables, requiring zero FLOPs and can be performed during data preprocessing. Fig. 4 shows an example of this operation.

ARM's compute-optimal setup favors bigger models. MDM and MDM-Prime-v2 instead favor more training tokens — a good fit for modern recipes (e.g., LLaMA) that shrink the model and train longer for cheaper inference.


1.1B-Scale Pretraining: Zero-Shot Commonsense Reasoning

We train a 1.1B-parameter model on 540B tokens from SlimPajama, matching the setup of TinyLLaMA (ARM) and SMDM (MDM).


Figure 6. Zero-shot accuracies evaluated on eight commonsense reasoning benchmarks. Higher values correspond to better performance.

MDM-Prime-v2 achieves the highest average accuracy (49.42%) across eight commonsense reasoning benchmarks against similar-sized ARM and MDM baselines (GPT-Neo, OPT, Pythia, Bloom, SMDM, TinyLLaMA), beating SMDM — the MDM baseline trained under an identical setup — by 4.87 points, with the largest gains on SciQ and McTaco.

Errata: Dependency Breaks ELBO

errata note

The original MDM-Prime-v2 preprint (Mar. 30, 2026) reported that the model exhibits more favorable compute-optimal scaling than autoregressive models (ARMs). The training objective used in those comparisons, however, is not a valid evidence lower bound (ELBO): prior work (EDLM) proposed capturing the joint distribution over sub-tokens, which breaks the independence assumption the bound relies on, so the resulting loss is not actually a bound on the data negative log-likelihood. We discuss this issue and its implications in a dedicated errata note.
